# Expense Tracker: дизайн первой версии

## Цель и границы

Пользователь отправляет фото чека, фото списка покупок или текстовый список в беседе ChatGPT либо Codex. Модель извлекает позиции и через подключённый MCP сохраняет расходы. Пользователь открывает сайт изредка, чтобы посмотреть, сколько потратил. Валюта первой версии — только PLN. Основной сценарий считается успешным, когда после одной отправки разборчивого фото позиции появляются в статистике без ручного переноса на сайт.

Первая версия предназначена для личного использования, но записи привязаны к учётной записи, чтобы данные разных пользователей не смешивались. Telegram и другие мессенджеры не входят в первую версию. Фотографии не сохраняются: MCP получает структурированные данные, подготовленные моделью. Отдельный сервис OCR и вызовы платного API для распознавания не нужны.

Под «любой беседой» понимается беседа ChatGPT или Codex, где пользователю доступно это MCP подключение. Клиент может требовать включить подключение в новой беседе; приложение не может автоматически сделать инструмент доступным во всех беседах. После записи модель сообщает сохранённую сумму и число позиций.

## Выбранный подход

Сайт размещается на Vercel как приложение Next.js. Он показывает статистику, выполняет вход через Supabase Auth и размещает экран согласия на доступ MCP клиента. Supabase размещает базу данных, Auth и Edge Function с удалённым MCP сервером. Supabase сам управляет лежащим в основе Postgres: отдельный хостинг базы и Auth0 не требуются.

Рассматривались загрузка фото на сайт и бот в мессенджере. Первая заставила бы регулярно пользоваться сайтом, вторая добавила бы ещё одну интеграцию. Разбор изображения в чате с последующей записью через MCP ближе к желаемому действию пользователя.

## Данные и вычисления

Один документ покупки содержит владельца, дату покупки, необязательное название магазина, валюту `PLN`, итог в целых грошах, время создания и идентификатор для защиты от повторной отправки. У документа есть позиции: название, количество, итог позиции в грошах и категория. Итог позиции уже учитывает количество. Скидки и возвраты могут быть отрицательными позициями; итог документа равен сумме всех позиций. Исходное фото и полный текст беседы не сохраняются.

Категории первой версии: продукты, кафе, дом, транспорт, здоровье, одежда, другое. Модель выбирает категорию при записи; пользователь может затем исправить её через чат. Статистика считает чистые расходы по дате покупки в часовом поясе Europe/Warsaw. Если на списке нет даты, используется текущая дата этого пояса. Название магазина необязательно. Денежные расчёты выполняются целыми грошами; интерфейс отображает PLN с двумя десятичными знаками.

## Поток записи и исправления

1. Пользователь присылает фото или текст и просит записать покупки. Модель извлекает позиции, количества, цены, дату и магазин, если они видны.
2. Если не читается сумма позиции, модель уточняет её. Если видимый итог чека расходится с суммой распознанных позиций, модель показывает расхождение и уточняет данные до записи. Отсутствие магазина допустимо.
3. Модель вызывает MCP инструмент записи одного документа с позициями. Сервер проверяет схему, авторизацию, валюту, границы денежных значений и равенство итогов, а затем сохраняет документ и позиции атомарно.
4. Сервер распознаёт повтор вызова по идентификатору отправки. Дополнительно он сравнивает дату, магазин, сумму и нормализованные позиции с существующими записями. При вероятном дубле ничего не записывает и возвращает кандидата; после явного подтверждения пользователь может сохранить действительно повторную покупку.
5. Для исправления в чате доступны просмотр недавних документов, просмотр одного документа и замена его данных. Ошибочную запись можно удалить только по явному запросу пользователя. Все инструменты действуют только с данными текущего пользователя.

MCP инструменты возвращают понятные ошибки для невалидных сумм, отсутствующих позиций, недоступных записей и неподтверждённого дубля. Запись не должна превращать неразборчивый чек в выдуманные суммы.

## Сайт

После входа главная страница показывает сумму за текущий календарный месяц, сравнение с полным предыдущим календарным месяцем, график расходов по дням, разбивку по категориям и последние документы с позициями. Пользователь может выбрать другой месяц и открыть детали документа. Интерфейс адаптирован для телефона и компьютера. Первая версия сайта предназначена для просмотра; исправление и удаление выполняются через чат.

При пустой базе сайт показывает нулевую статистику и короткую подсказку о записи через чат. Ошибки загрузки отображаются явно, без подмены их нулевыми суммами.

## Доступ и развёртывание

Supabase Auth служит единой учётной записью для сайта и MCP; вход на сайт — по ссылке, отправленной на email. Для удалённого MCP включается OAuth 2.1 сервер Supabase с динамической регистрацией клиентов и экраном согласия в Next.js. Edge Function публикует OAuth protected-resource metadata, проверяет токен при каждом вызове и обращается к базе с правами этого пользователя. Таблицы защищены Row Level Security по `user_id`; секретный ключ Supabase не попадает в браузер или MCP ответы.

Развёртывание состоит из проекта Supabase и проекта Vercel. Репозиторий содержит миграции, код Edge Function, приложение Next.js, пример переменных окружения и инструкцию по локальному запуску и подключению MCP в ChatGPT/Codex. Фактическое подключение к аккаунтам и проверка фото в этих клиентах требуют доступных пользователю проектов и включённого MCP.

## Проверка готовности

- Автоматические тесты проверяют перевод PLN в гроши, отрицательные корректировки, суммы документов, месячные и категорийные итоги, границу месяцев в Europe/Warsaw и возможные дубли.
- Проверки доступа подтверждают, что один пользователь не читает и не меняет документы другого, а запрос без токена не вызывает инструменты записи.
- MCP Inspector подтверждает обнаружение и схемы инструментов, успешную запись, исправление, удаление и понятные ошибки.
- На локальном сайте проверяются пустое состояние, статистика с тестовыми данными, детали документа и мобильная ширина.
- После настройки аккаунтов пробный чек проходит весь путь: фото в чате → MCP → запись в Supabase → отображение на сайте. До этой проверки нельзя утверждать, что интеграция с конкретным ChatGPT/Codex аккаунтом работает.

## Вне первой версии

Мультивалютность, бот в мессенджере, хранение исходных фото, автоматическое распознавание на сервере, бюджетные лимиты, банковские интеграции, общий семейный доступ и ручное редактирование на сайте.
