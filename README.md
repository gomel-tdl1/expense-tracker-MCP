# Учёт расходов через чат и MCP

Личный учёт покупок в польских злотых. Пользователь отправляет фото чека или список покупок в ChatGPT, Claude либо другой MCP-клиент. Клиент распознаёт позиции и вызывает инструмент записи; Supabase хранит расходы, а сайт на Next.js показывает статистику. Каждый желающий может развернуть собственный экземпляр в своих аккаунтах Supabase и Vercel.

> Фото анализирует чат с поддержкой изображений. MCP-сервер получает структурированные позиции и не хранит исходное фото. По одному фото без текста запись в произвольном чате не гарантирована: проверьте, что коннектор включён и инструмент записи был вызван.

## Возможности и ограничения

- Запись всех позиций чека с количеством, суммой строки, датой, магазином и категорией.
- Статистика за месяц: общая сумма, сравнение с предыдущим месяцем, расходы по дням, категории и история чеков.
- Чтение, исправление и удаление чеков через пять MCP-инструментов.
- Предупреждение о возможном повторе чека; повтор запроса с тем же идентификатором не создаёт вторую запись.
- Изоляция данных пользователей через Supabase Auth и Row Level Security (RLS).

Валюта сейчас только **PLN**. Суммы хранятся в целых грошах. Дата без указания на чеке определяется по часовому поясу Europe/Warsaw. Есть 42 готовые категории; их полный список — в [categories.ts](supabase/functions/_shared/categories.ts). Среди них «Алкоголь», «Топливо», «Аптека», «Питомцы» и «Подписки». Явно названное алкогольное пиво записывается как алкоголь, безалкогольное — как продукты.

Сайт предназначен для просмотра расходов. Исправление и удаление выполняются через чат. Публичной регистрации пользователей нет: администратор заранее создаёт каждому email и пароль в Supabase.

## Устройство проекта

~~~mermaid
flowchart LR
    A[Фото или текст в чате] --> B[Клиент распознаёт позиции]
    B --> C[MCP Edge Function]
    C --> D[Supabase Auth и RLS]
    D --> E[(Чеки и позиции в Postgres)]
    E --> F[Сайт Next.js]
~~~

| Часть | Файлы | Назначение |
| --- | --- | --- |
| Сайт | src/app, src/components | Вход, статистика и экран OAuth consent |
| Загрузка и расчёты | src/lib/expenses.ts, src/lib/stats.ts | Чеки и месячные итоги |
| MCP | supabase/functions/mcp | Удалённый сервер Streamable HTTP |
| Правила чеков | supabase/functions/_shared | Суммы, дата, категории, дубли |
| База | supabase/migrations | Таблицы, ограничения, RLS, функции записи |
| Тесты | tests, supabase/tests/database | Логика TypeScript и SQL |

Таблица expense_receipts хранит владельца, дату, магазин, итог, идентификатор отправки и отпечаток чека. Таблица expense_items хранит позиции, порядок, количество, категорию и сумму строки. Сумма строки уже учитывает количество; скидки и возвраты могут быть отрицательными позициями. Итог чека должен равняться сумме позиций.

Сайт входит по email и паролю. MCP-клиент проходит отдельный OAuth 2.1 вход и получает разрешение на странице /oauth/consent. Пользовательские запросы MCP выполняются под его учётной записью; RLS ограничивает чтение его чеками. Сервисный ключ Supabase не нужен ни сайту, ни MCP-клиенту. SMTP и почтовые шаблоны для выбранного входа по паролю не нужны.

## Локальная разработка

Команды приведены для macOS, Linux или WSL. Понадобятся Git, Node.js 24 (на нём проект проверялся), pnpm 11.23.0, запущенный Docker и Deno 2 для локальной Edge Function. Версии основных пакетов закреплены в package.json и pnpm-lock.yaml. Установку инструментов см. в документации [Node.js](https://nodejs.org/), [pnpm](https://pnpm.io/installation), [Docker](https://docs.docker.com/get-docker/) и [Deno](https://docs.deno.com/runtime/getting_started/installation/); [требования Supabase для MCP](https://supabase.com/docs/guides/ai-tools/byo-mcp).

### 1. Скачать код и зависимости

~~~bash
git clone https://github.com/gomel-tdl1/expense-tracker-MCP.git
cd expense-tracker-MCP
pnpm install
~~~

Если pnpm отсутствует, установите версию из поля packageManager в package.json. Команда pnpm supabase использует CLI из зависимостей проекта; глобально устанавливать Supabase CLI не требуется.

### 2. Запустить локальную базу

~~~bash
pnpm supabase start
pnpm supabase db reset
pnpm supabase status -o env
~~~

Обычный db reset пересоздаёт **локальную** базу и применяет миграции из supabase/migrations. Он удаляет локальные тестовые записи. После первого запуска для продолжения работы обычно достаточно pnpm supabase start. Не запускайте db reset --linked на рабочем удалённом проекте: эта команда удалит его данные.

Скопируйте образец окружения:

~~~bash
cp .env.example .env.local
~~~

Возьмите из вывода status -o env значения API_URL и PUBLISHABLE_KEY и заполните две строки в .env.local:

~~~dotenv
NEXT_PUBLIC_SUPABASE_URL=<API_URL>
NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY=<PUBLISHABLE_KEY>
~~~

Не добавляйте сюда SERVICE_ROLE_KEY, секретные ключи или пароли. Файл .env.local исключён из Git.

### 3. Создать пользователя

Откройте локальную Supabase Studio: http://127.0.0.1:54323. В Authentication → Users → Add user создайте пользователя с email и паролем. Самостоятельная регистрация на сайте отключена.

### 4. Запустить MCP и сайт

В двух терминалах из каталога проекта:

~~~bash
# Терминал 1
pnpm supabase functions serve mcp
~~~

~~~bash
# Терминал 2
pnpm dev
~~~

Откройте http://localhost:3000/login, войдите созданным пользователем и перейдите на /dashboard. Локальный MCP URL: http://127.0.0.1:54321/functions/v1/mcp. Для подключения облачных ChatGPT и Claude понадобится публичный HTTPS URL после развёртывания либо временный HTTPS-туннель.

## Развёртывание собственного экземпляра

Вам нужны свой проект Supabase, хостинг Next.js (ниже используется Vercel) и клиент с поддержкой удалённого MCP. Ключи и URL автора репозитория использовать не нужно.

### 1. Настроить Supabase Auth

1. Создайте проект в [Supabase](https://supabase.com/dashboard). Project ref находится в адресе Dashboard вида https://supabase.com/dashboard/project/<PROJECT_REF>; Project URL имеет вид https://<PROJECT_REF>.supabase.co.
2. Проверьте, что пользовательские JWT подписываются асимметричным ключом ES256 или RS256: middleware MCP сверяет токены с JWKS. [Руководство Supabase MCP](https://supabase.com/docs/guides/ai-tools/byo-mcp).
3. В Authentication → Sign In / Providers оставьте Email включённым и отключите Allow new users to sign up. В Authentication → Users → Add user создайте нужных пользователей с паролями; при необходимости подтвердите email в интерфейсе. Не вставляйте записи напрямую в auth.users.
4. В Authentication → OAuth Server включите OAuth 2.1, задайте Authorization Path /oauth/consent и включите Dynamic Client Registration. [Настройка OAuth Server](https://supabase.com/docs/guides/auth/oauth-server/getting-started).

Локальный supabase/config.toml задаёт Site URL http://localhost:3000 для локального запуска. Настройки облачного Auth **не переносятся** командой db push; проверьте их в Dashboard отдельно.

### 2. Применить миграции и опубликовать MCP

В корне репозитория:

~~~bash
pnpm supabase login
pnpm supabase link --project-ref <PROJECT_REF>
pnpm supabase migration list
pnpm supabase db push
pnpm supabase functions deploy mcp --no-verify-jwt
~~~

На новом проекте db push применит обе миграции по порядку. На существующем проекте сначала сравните локальную и удалённую историю в migration list. Если она расходится, разберите причину до db push; не накладывайте начальную миграцию повторно на готовые таблицы. [Миграции Supabase](https://supabase.com/docs/reference/cli/supabase-migration-list), [публикация функций](https://supabase.com/docs/guides/functions/deploy).

Флаг --no-verify-jwt отключает проверку только на шлюзе Edge Function, чтобы MCP-клиент мог пройти OAuth discovery. Внутри функции пользовательский токен проверяет withSupabase({ auth: 'user' }), а RLS ограничивает данные. URL сервера:

~~~text
https://<PROJECT_REF>.supabase.co/functions/v1/mcp
~~~

Не выполняйте config push с локальным Site URL http://localhost:3000 в production.

### 3. Развернуть сайт

1. Импортируйте свой форк или копию репозитория в [Vercel](https://vercel.com/new) как Next.js проект.
2. Добавьте две переменные окружения для Production:

   | Имя | Значение |
   | --- | --- |
   | NEXT_PUBLIC_SUPABASE_URL | https://<PROJECT_REF>.supabase.co |
   | NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY | Publishable key своего проекта |

   Project URL и publishable key доступны через кнопку Connect проекта Supabase или Settings → API Keys. Секретный/service role key здесь не нужен. [Ключи Supabase](https://supabase.com/docs/guides/getting-started/api-keys).
3. Опубликуйте сайт. Если репозиторий подключён к Vercel, push в production-ветку (обычно main) создаёт новую сборку. [Git deployments Vercel](https://vercel.com/docs/git).
4. После получения постоянного URL укажите его в Supabase Authentication → URL Configuration → Site URL, например https://expenses.example.com. Экран OAuth будет по адресу <SITE_URL>/oauth/consent. Для нынешнего входа по паролю Redirect URL /auth/callback не нужен.
5. Откройте <SITE_URL>/login, войдите пользователем из Supabase Auth и проверьте /dashboard.

### 4. Проверить связку

Подключите MCP к клиенту по инструкции ниже. Запишите тестовый чек и убедитесь, что инструмент вернул status created, а сумма и позиции появились на сайте под **тем же пользователем**. Затем проверьте recent_receipts, исправление и удаление тестового чека. Возможный повтор возвращает duplicate_candidate и требует подтверждения.

## Подключение ChatGPT и Claude

Используйте URL https://<PROJECT_REF>.supabase.co/functions/v1/mcp как **удалённый HTTP MCP** с OAuth. Локальное подключение типа STDIO в Codex или Claude Desktop не делает сервер доступным в мобильном чате.

### ChatGPT

1. В ChatGPT включите Settings → Security and login → Developer mode, если этот режим доступен аккаунту.
2. Откройте [ChatGPT Plugins](https://chatgpt.com/plugins), нажмите + и создайте подключение, указав полный HTTPS URL MCP.
3. Проверьте обнаруженные инструменты, включая record_receipt; установите личный плагин и пройдите OAuth вход в свой Supabase.
4. На телефоне под тем же аккаунтом начните новый чат, включите плагин через меню инструментов или @, приложите фото чека и попросите записать покупки.
5. После изменения схемы или описаний инструментов откройте подключение в ChatGPT Plugins, нажмите Refresh и начните новый чат.

Доступность Developer mode зависит от аккаунта. Мобильный ChatGPT поддерживает плагины, доступные этому аккаунту, но автоматический вызов инструмента по одному фото без текста не гарантирован. [Подключение MCP в ChatGPT](https://developers.openai.com/plugins/deploy/connect-chatgpt), [плагины на мобильном](https://learn.chatgpt.com/docs/plugins).

### Claude

1. На [claude.ai](https://claude.ai/) откройте Customize → Connectors → + Add → Add custom connector.
2. Укажите имя и тот же HTTPS URL MCP. Для защищённого сервера используйте OAuth; если потребуется выбрать способ регистрации OAuth-клиента, выберите автоматическую регистрацию.
3. Войдите пользователем своего Supabase и разрешите доступ.
4. В мобильном Claude под тем же аккаунтом включите коннектор для беседы через + → Connectors, приложите фото и попросите записать чек.

Удалённые коннекторы работают в мобильном Claude; добавление коннекторов непосредственно с телефона может оставаться бета-функцией, поэтому начальную настройку удобнее выполнять в браузере. Совместимость **вашего развернутого экземпляра** проверяйте тестовым вызовом. [Custom connectors Claude](https://support.claude.com/en/articles/11175166-get-started-with-custom-connectors-using-remote-mcp), [мобильные коннекторы](https://support.claude.com/en/articles/11176164-use-connectors-to-extend-claude-s-capabilities).

Другие клиенты подходят, если поддерживают удалённый Streamable HTTP MCP, OAuth и инструменты записи. Поддержка изображений и автоматический выбор инструмента зависят от клиента.

## Работа с чеками

Пример запроса вместе с фото:

> Запиши все покупки с этого чека в PLN. Если позиция или цена не читается либо сумма строк не совпадает с итогом, уточни перед записью. После записи назови сумму и количество позиций.

Чтобы исправить чек: «Покажи последние чеки, найди чек из магазина X и исправь категорию пива на алкоголь». Чтобы удалить: укажите конкретный чек и явно попросите удалить его. Старые чеки не переклассифицируются автоматически после изменения правил.

| Инструмент | Действие |
| --- | --- |
| record_receipt | Сохраняет чек или сообщает о возможном дубле |
| recent_receipts | Показывает последние чеки пользователя |
| receipt_details | Возвращает чек и позиции по ID |
| replace_receipt | Заменяет дату, магазин и **полный** список позиций |
| delete_receipt | Удаляет указанный чек по явному запросу |

Перед replace_receipt клиент должен прочитать старый чек, чтобы сохранить неизменённые позиции. Если цена не читается или итог не равен сумме строк, запись отклоняется вместо угадывания.

## Изменение проекта

### Проверки

После изменения TypeScript или интерфейса:

~~~bash
pnpm test
pnpm exec tsc --noEmit
pnpm build
~~~

После изменения миграций или Edge Function с запущенным локальным Supabase:

~~~bash
pnpm supabase test db
pnpm supabase db lint --level error
~~~

Тесты TypeScript находятся в tests, SQL-тесты — в supabase/tests/database. Автоматические тесты не заменяют проверку OAuth и вызова MCP на опубликованном экземпляре. Подробный список приёмки — в [docs/deployment.md](docs/deployment.md).

### Интерфейс и настройки отображения

- Светлая и тёмная темы; переключатель в шапке. По умолчанию — тёмная.
- Языки RU / EN / PL: подписи, все категории, даты и формат сумм. Названия магазинов и товаров остаются такими, как записаны в чеке. Валюта всегда PLN.
- Кнопка паузы отключает декоративные анимации. Системная настройка `prefers-reduced-motion` также учитывается.
- Выбор хранится в cookies `expense-locale`, `expense-theme`, `expense-motion` на этом устройстве на год. Сервер читает их при первом отображении страницы.
- Нажмите категорию в обзоре: под графиком появятся **позиции этой категории за выбранный месяц**, их магазины, даты, количество и общая сумма. Скидки вычитаются. Закрыть список можно повторным нажатием категории или кнопкой «Закрыть».
- Значки магазинов — локальные типографические монограммы, **не официальные логотипы**. Нет запросов к сервисам логотипов или хранения изображений чеков.

Основные файлы: [dashboard-view.tsx](src/components/dashboard-view.tsx) — компоновка, [globals.css](src/app/globals.css) — темы и анимации, [i18n.ts](src/lib/i18n.ts) — переводы, [merchant.ts](src/lib/merchant.ts) — монограммы, [category-insights.tsx](src/components/category-insights.tsx) — интерактивный просмотр категории.

Проверка вручную: войдите, выберите месяц с покупками, откройте категорию и сверяйте её позиции и итог. Переключите каждый язык, тему и анимации, затем перезагрузите страницу. Проверьте узкий экран, пустой месяц и навигацию клавишей Tab. Обновление интерфейса не требует миграций или повторной публикации MCP — достаточно нового deployment фронтенда.

### Добавление категории

1. Добавьте ключ и подпись в [categories.ts](supabase/functions/_shared/categories.ts). Этот файл используют MCP, проверка чеков и сайт. Добавьте английский и польский переводы в [i18n.ts](src/lib/i18n.ts); TypeScript проверяет полноту словарей.
2. Создайте **новую** миграцию в supabase/migrations, обновив expense_items_category_check и проверку validate_expense_items. Не редактируйте уже применённую production-миграцию.
3. Добавьте проверки записи и подсчёта новой категории. При необходимости обновите описание категории в supabase/functions/mcp/tools.ts.
4. Примените миграцию через db push, опубликуйте MCP-функцию, отправьте сайт в production-ветку и обновите метаданные подключения. Порядок важен: новая категория должна приниматься базой и быть известна фронтенду.

Если база уже выдаёт новый ключ, а сайт ещё использует старую версию списка, в статистике могут появиться пустые строки и NaN zł. Проверяйте успешный deployment Vercel после изменения категорий.

### Участие

Создайте отдельную ветку, внесите изменение вместе с миграцией и необходимыми проверками, выполните команды выше и откройте pull request с описанием поведения и способа проверки. Не публикуйте .env.local, токены, пароли и реальные чеки.

В репозитории пока нет файла LICENSE. Для ясных условий стороннего использования владельцу стоит выбрать и добавить лицензию.

## Частые проблемы

| Симптом | Проверка |
| --- | --- |
| Supabase не запускается | Docker работает, нужные локальные порты свободны. |
| Нельзя войти на сайт | Пользователь создан в Supabase Auth, email подтверждён при необходимости, пароль и две переменные окружения относятся к одному проекту. |
| OAuth ведёт на localhost | В облачном Supabase Site URL всё ещё локальный; установите production URL и проверьте Authorization Path /oauth/consent. |
| Клиент не видит инструменты | Указан точный URL /functions/v1/mcp, функция опубликована, выбрано удалённое HTTP-подключение, метаданные обновлены. |
| Без токена сервер отвечает 401 | Это ожидаемо для защищённого MCP; завершите OAuth вход через клиент. |
| receipt total differs from item sum | Сверьте все позиции, скидки и напечатанный итог. |
| duplicate_candidate | Похожий чек уже сохранён; подтвердите повтор только для отдельной реальной покупки. |
